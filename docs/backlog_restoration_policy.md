# Политика восстановления истории диалога

> **Статус:** реализовано. Документ сохраняется как описание действующего контракта `DialogueBacklog` и `SaveData` v3. Актуальный общий статус систем см. в `docs/eternum_feature_tracker.md`.

## Назначение

История диалога должна восстанавливаться вместе с конкретным сохранением и не смешивать реплики из будущей ветки после загрузки более старого слота.

## Действующий контракт

- `DialogueBacklog` хранит до 100 последних записей `speaker/text`.
- Manual, Auto и Quick сохраняют ограниченный снимок истории в `SaveData` v3.
- После Load, Quick Load или Continue текущая история **заменяется** снимком из выбранного сохранения. Объединение со старой runtime-историей запрещено.
- Переход между `DialogueSceneData` сам по себе историю не очищает.
- New Game начинает с пустой истории.
- Старые v1/v2 сохранения без снимка истории остаются загружаемыми; для них используется безопасный пустой fallback.
- Повреждение необязательного backlog-снимка не должно делать валидное основное сохранение незагружаемым.

## Защита от дублей при восстановлении

Снимок уже содержит видимую текущую строку или `resultText` выбранного варианта. Поэтому во время restore используется короткий scoped-suppression добавления в backlog. Он действует только на восстановительные вызовы и всегда снимается через безопасный `try/finally`-контракт.

Нельзя использовать долгоживущий флаг подавления: после ошибки он может начать терять реальные новые реплики.

## Что хранится

```csharp
[Serializable]
public sealed class BacklogEntryData
{
    public string speaker;
    public string text;
}
```

Хранятся только сырые `speaker/text`, максимум 100 записей от старых к новым. TMP-разметка, цвета, timestamps, UI-state, прогресс typewriter и отдельная identity записи не сериализуются.

## Choice result

Если сохранение сделано на результате выбора, сохраняются обычные choice-state поля и сам `resultText` как запись истории. При восстановлении выбор повторно не применяется и stat-delta повторно не начисляется.

## Отдельность от seen-state

`DialogueReadHistory` — отдельное профильное состояние для seen-aware Skip. Это не player-facing History и не источник восстановления backlog.

## Основные гарантии

- загрузка старого сохранения не оставляет реплики будущей ветки;
- текущая строка/result beat не дублируется;
- v1/v2 остаются совместимыми;
- `SaveData` остаётся v3;
- backlog и `DialogueReadHistory` не смешиваются;
- rollback из этого контракта не следует и реализованным не считается.
