# Принципы UI/UX

- Удобство и читаемость важнее декоративности.
- Интерфейс должен оставаться пригодным даже без финального арта.
- Главное меню и другие экраны не следует перегружать ненужными действиями.
- Каждый player-facing control должен иметь понятную пользу и реальный runtime-эффект.
- Для дискретного выбора одного значения используется `dropdown`.
- Для непрерывного значения используется `slider`.
- Для логического значения используется `toggle`.
- Опасное/разрушающее действие не получает небезопасный фокус по умолчанию.
- Взаимодействие клавиатурой, мышью и геймпадом должно быть предсказуемым.
- Главное меню, игровое меню, настройки и Save/Load должны ощущаться одной UI-системой.
- Не создавать новый UI framework ради одного экрана.
- Хорошие игры/VN и проверенные UX-паттерны используются как референс, а не копируются буквально.
- Не копировать чужие assets, code или уникальный layout.
- Перед крупным redesign интерфейса сравнить несколько сильных референсов и сформулировать решение именно для HIF.
- Внешнее visual research начинается с сильных benchmark-референсов: признанных визуальных новелл и качественных релевантных игр, а не случайного набора примеров.
- После общего benchmark искать task-specific примеры для конкретного экрана/взаимодействия; при необходимости добавлять общий UX/accessibility guidance.
- Известность игры не доказывает качество каждого её экрана. Сравнивать композицию, иерархию, интервалы, читаемость, визуальный вес, согласованность и состояния взаимодействия.

## Источники решений

**Интернет** — идеи, UX-паттерны и внешние референсы.

**Документация репозитория** — утверждённые решения How I Fall и главный источник истины для реализации.
